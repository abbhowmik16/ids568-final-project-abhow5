Grounding means that a generated answer is supported by the retrieved context. In a strong RAG system, the answer should reflect the content of the retrieved chunks rather than invent unsupported claims.
Evaluation of a RAG system usually includes both retrieval quality and answer quality. Retrieval quality can be measured using metrics such as precision at k or recall at k, along with manual relevance judgments. Answer quality can be reviewed qualitatively by checking whether the response stays faithful to the retrieved context.
It is important to separate retrieval failure from generation failure. Retrieval failure happens when the system brings back the wrong chunks. Generation failure happens when the correct chunks are retrieved, but the model still produces an answer that is misleading, incomplete, or hallucinated.
Latency should also be measured. A useful evaluation report often records retrieval latency, generation latency, and end-to-end latency. Failure analysis is important because understanding when the system fails is as valuable as measuring when it succeeds.
